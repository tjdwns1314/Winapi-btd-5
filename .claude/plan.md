# WinAPI 기반 절차적 풍선 타워 디펜스 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | Balloon Defense (가칭) |
| 장르 | 2D 타워 디펜스 |
| 개발 기간 | 4주 |
| 개발 환경 | C++20, WinAPI, Direct2D + WIC |
| 핵심 기술 | A* 경로 탐색, 절차적 맵 생성, 타일 기반 렌더링 |
| 목표 | 매번 달라지는 맵에서 풍선을 막는 싱글플레이 타워 디펜스 제작 |

플레이어는 골드를 사용해 타워를 설치하고, 생성 지점에서 목표 지점으로 이동하는 풍선 형태의 적을 처치한다. 맵은 매 게임마다 절차적으로 생성되며, A* 알고리즘으로 적의 이동 가능한 경로를 검증하고 계산한다.

## 2. 핵심 게임 규칙

| 항목 | 내용 |
|---|---|
| 승리 조건 | 모든 웨이브의 적 처치 |
| 패배 조건 | 적이 도착 지점에 도달하여 라이프가 0이 됨 |
| 초기 라이프 | 100 |
| 초기 골드 | 600 |
| 자원 | 적 처치 시 골드 획득, 타워 설치·업그레이드에 사용 |
| 적 | Red→Blue→Green→Yellow→Pink→Black/White→Lead→Zebra→Rainbow→Ceramic 색상 등급 체인을 가진 일반 풍선 + 자체 체력을 가진 보스 풍선(내부에 하위 풍선들을 담고 있음) |
| 타워 | 사거리 안의 적을 자동으로 탐지하여 공격 |
| 맵 | 격자 기반의 절차 생성 맵, 스테이지 1-1 / 1-2 / 1-3 3종, 뒤로 갈수록 난이도 상승 |
| 웨이브 | 일정 시간 또는 이전 웨이브 종료 후 적이 순차 등장 |

## 3. 절차적 맵 생성

맵은 스테이지 단위(1-1, 1-2, 1-3)로 생성한다. 시작점과 도착점은 맵의 양쪽 가장자리에 배치하고, 그 사이 경로는 **미로(maze) 형식**으로 생성한다. 경로로 사용되지 않는 나머지 그리드 칸은 전부 타워 설치가 가능하다 — 이전 버전의 "길과 분리된 일반 지형" 개념은 폐기하고, 셀 상태를 **길 / 설치 가능** 두 가지로 단순화한다.

### 생성 과정

```text
맵 초기화
  → 시작점·도착점 배치 (양쪽 가장자리)
  → 스테이지 난이도 가중치 로드 (1-1 < 1-2 < 1-3)
  → 미로 알고리즘으로 시작점~도착점 경로 생성
  → A* 알고리즘으로 경로 탐색 및 유효성 검증
  → 경로가 없거나 난이도 기준(길이·분기 수 등) 미달이면 재생성
  → 길이 아닌 모든 칸을 타워 설치 가능 칸으로 확정
  → 유효한 맵 확정 및 적 이동 경로 저장
```

### 권장 규칙

- 맵 크기: 20 × 15 타일
- 시작점: 왼쪽 가장자리의 무작위 위치 / 도착점: 오른쪽 가장자리의 무작위 위치
- 길에는 타워 설치 불가, **길이 아닌 모든 칸은 타워 설치 가능**
- 스테이지별 난이도 가중치로 미로 복잡도(분기 수, 막다른 길 비율, 경로 길이)를 조절해 1-1 → 1-2 → 1-3 순으로 어려워지도록 생성 스크립트 설계
- 길이가 너무 짧거나 단순한 맵은 재생성하여 플레이 다양성 확보

## 4. A* 알고리즘 활용

A* 알고리즘은 절차 생성 맵에서 적이 이동할 수 있는 경로를 계산하고 검증하는 핵심 기능이다.

| 요소 | 역할 |
|---|---|
| 시작 노드 | 적 생성 지점 |
| 목표 노드 | 플레이어가 방어해야 하는 도착 지점 |
| G 비용 | 시작점부터 현재 타일까지 실제 이동 비용 |
| H 비용 | 현재 타일에서 도착점까지의 추정 비용(맨해튼 거리) |
| F 비용 | `F = G + H`, 다음 탐색 노드를 결정하는 기준 |

초기 구현에서는 맵 생성 때 계산한 하나의 유효 경로를 모든 적이 공유한다. 타워는 길 밖에만 설치하도록 하여 경로가 막히는 문제를 방지한다. 시간 여유가 있다면 타워 설치에 따른 경로 재계산 기능을 확장 기능으로 구현한다.

## 5. 풍선 등급 체계와 충돌 판정

### 풍선 등급 체인 (`Client/BloonType.h` 기준)

Red → Blue → Green → Yellow → Pink → Black/White → Lead → Zebra → Rainbow → Ceramic 순으로 이어지는 색상 등급 체인을 그대로 사용한다.

**터짐 규칙**: 풍선이 죽으면 체인상 바로 아래 등급의 풍선(들)이 생성된다 (예: Ceramic → Rainbow, Zebra → Lead). 더 내려갈 하위 등급이 없는 최하위 등급(Red)이 터지면 하위 풍선을 생성하지 않고 그대로 삭제(destroy)한다.

**이동 속도**: `Speed(tier) = 60 + 5 × (tier - 1)` (tier: Red=1 ~ Ceramic=10, 단위는 px/s에 준하는 임의 단위). Red=60, Blue=65, ..., Ceramic=105로 등급이 높을수록 조금씩 빨라진다. 보스1/보스2는 몸집이 크므로 고정값 30으로 더 느리게 이동한다.

### 충돌 판정

| 대상 | 판정 방식 | 이유 |
|---|---|---|
| 일반 풍선 (Red~Ceramic) | AABB | 회전 없이 이동만 하므로 축 정렬 사각형으로 충분 |
| 보스 풍선 | OBB | 직사각형 형태이며 타원형 경로를 따라 이동 방향에 맞춰 회전하기 때문에 회전을 반영한 충돌 박스가 필요 |

### 보스 풍선

- 형태: 직사각형(예: 사진 참고 — 위장 패턴의 캡슐/포탄형 몸체), 이동 방향에 따라 회전
- 자체 체력을 별도로 가지며, 그 체력이 0이 되면 파괴된다.
- 파괴 시 내부에 담고 있던 하위 개체를 방출한다 (컨테이너 역할).
- 보스는 2단계로 구성되며, 보스2가 보스1을 담고, 보스1이 Ceramic을 담는 체인 구조다.

| 보스 | 체력 | 파괴 시 방출 |
|---|---|---|
| 보스1 | 200 | Ceramic 4개 |
| 보스2 | 700 | 보스1 4개 |

## 6. UI 기획

UI는 풍선 타워 디펜스의 정보 구조를 참고하되, 아이콘·그래픽·명칭은 직접 제작한다.

```text
┌───────────────────────────────────────────────────────┐
│ [웨이브] 3 / 10      [라이프] ♥ 100     [골드] $ 850   │
├───────────────────────────────┬───────────────────────┤
│                               │ 타워 선택 패널         │
│          절차 생성 맵          │ [기본 타워]  $200      │
│      시작점 → 길 → 도착점      │ [원거리 타워] $350      │
│                               │ [범위 타워]  $500      │
│                               │                       │
│                               │ 선택 타워 정보         │
│                               │ 판매 / 업그레이드      │
├───────────────────────────────┴───────────────────────┤
│ [시작 / 일시정지]        [배속] x1 / x2               │
└───────────────────────────────────────────────────────┘
```

- 상단: 현재 웨이브, 남은 라이프, 골드
- 중앙: 절차 생성 맵, 길, 타워, 적, 투사체
- 오른쪽: 타워 구매 버튼과 선택된 타워의 정보
- 하단: 웨이브 시작, 일시정지, 게임 속도 조절
- 타워 선택 시: 공격 범위, 업그레이드, 판매 버튼 표시

## 7. 타워 스탯 설계

### 공통 프로퍼티

모든 타워는 다음 프로퍼티를 공통으로 가진다.

| 프로퍼티 | 타입 | 의미 |
|---|---|---|
| `_attackRange` | float | 공격 사거리 |
| `_damage` | float | 공격 데미지 |
| `_attackSpeed` | float | 공격 속도(초당 공격 횟수 또는 공격 주기) |
| `_grade` | int32 | 현재 등급, 1부터 시작 |
| `_canUpgrade` | bool | 다음 등급으로 업그레이드 가능 여부(최고 등급이면 false) |
| `_upgradeCost` | int32 | 다음 등급으로 올리는 데 필요한 비용 |
| `_attackCount` | int32 | 한 번의 공격으로 명중시킬 수 있는 풍선 개수 |

### 등급 시스템

- `_grade`는 1부터 시작하며, 업그레이드할 때마다 `_upgradeCost`를 지불하고 `_grade`가 1씩 오른다.
- 최대 등급은 5로 고정한다. `_grade == 5`가 되면 `_canUpgrade = false`로 더 이상 업그레이드할 수 없다.
- `_damage`: 선형 증가 (예: 등급마다 정해진 값만큼 증가 — 1 → 3처럼 등급별 목표값 테이블로 관리, 배율 아님)
- `_upgradeCost`: 배율 증가, 등급마다 1.5배
- `_attackSpeed`: 배율 증가, 등급마다 1.5배
- 정확한 데미지 테이블 값은 밸런싱 단계(3주차)에서 확정한다.
- **업그레이드 범위는 타워 인스턴스 단위다.** 맵에 배치된 타워 하나를 업그레이드해도 같은 종류의 다른 타워(맵에 이미 놓인 것/앞으로 놓을 것 모두)는 영향받지 않는다 — 전역 리서치형 업그레이드가 아니라 개별 타워 스탯 변경이다.

### 타워별 차별화

타워는 다음 3종으로 구성한다. 공격 사거리 판정 형태(방향성/원형)와 기본 사거리 길이로 구분한다.

| 타워 | 공격 판정 | 설명 |
|---|---|---|
| 기본 타워 | 방향성(전방) | 타워가 바라보는 방향(앞쪽)만 공격 — 원형이 아니라 정면 방향만 판정 |
| 범위 타워 | 원형 | 사거리 안에 들어오는 풍선을 방향 상관없이 전방위로 공격 |
| 원거리 타워 | 원형 | 범위 타워와 같은 원형 판정이지만, 기본 `_attackRange`가 더 긴 타워 |

- 타워 종류별 초기 스탯(`_attackRange`, `_damage`, `_attackSpeed`, `_attackCount`)은 전부 placeholder로 1을 사용한다. 공격 범위를 실제로 렌더링해서 눈으로 확인한 뒤 밸런싱 단계에서 수정한다.
- 기본 타워의 "바라보는 방향"은 배치 시 고정이 아니라, **타겟팅한 적을 향해 회전**한다.
- 지금 단계는 `Tower` 공통 프로퍼티 기획까지만 정리하고, 3종 타워 각각의 서브클래스(공격 판정 형태 포함)와 구체 수치 구현은 추후 진행한다.

## 8. 웨이브 설계

- 스테이지당 웨이브 수는 **10**으로 고정한다.
- 웨이브 수(10) = 풍선 등급 체인 단계 수(Red~Ceramic, Black/White를 한 단계로 묶어 10단계)와 정확히 일치시켜, **웨이브 W에서 등급 W가 새로 등장**하는 구조로 단순화한다 (Wave1=Red, Wave2=Blue, ..., Wave10=Ceramic).
- 웨이브가 뒤로 갈수록: (1) 총 스폰 수량이 늘어나고, (2) 그 웨이브에서 새로 등장한 상위 등급의 비중이 늘어난다 — 낮은 등급도 계속 섞여 나오지만 비중은 줄어든다.
- 1-1 / 1-2 / 1-3 모두 동일한 Wave→등급 매핑을 쓰되, **스폰 수량 배율**과 **보스 등장 빈도**로 스테이지 난이도를 구분한다 (맵의 미로 복잡도와는 별개의 축).

### 스폰 수량

`TotalCount(W) = base × stageMultiplier + growth × stageMultiplier × (W-1)`

| 스테이지 | stageMultiplier |
|---|---|
| 1-1 | 1.0 |
| 1-2 | 1.3 |
| 1-3 | 1.6 |

- `base = 20`, `growth = 15` (baseline, 밸런싱 단계에서 조정 가능) — 예: 1-1의 Wave1 = 20마리, Wave10 = 155마리

### 보스 등장

| 스테이지 | 보스1 등장 웨이브 | 보스2 등장 웨이브 |
|---|---|---|
| 1-1 | 5 | 10 |
| 1-2 | 4, 7 | 10 |
| 1-3 | 3, 6, 8 | 10 |

- 웨이브 10(마지막 웨이브)은 모든 스테이지 공통으로 보스2가 등장하는 최종 웨이브다.
- 정확한 수치(수량 계수, 보스 체력 스케일 등)는 밸런싱 단계에서 조정 가능한 시작점으로 삼는다.

### 웨이브 내 스폰 간격

`SpawnInterval(W) = max(0.3, 1.0 - 0.05 × (W-1))` (초) — 웨이브가 진행될수록 스폰 간격이 조금씩 짧아지다가 0.3초에서 하한을 둔다.

## 9. 투사체 설계

- 속도(`_speed`)는 placeholder로 1을 사용, 실제 날아가는 속도를 보고 밸런싱 단계에서 조정한다.
- 이동 방식: 유도(호밍) 없이 발사 시점의 방향으로 회전 없이 직진한다.
- 모양: 기본은 원형. 다트류처럼 회전이 필요한 투사체는 추후 타원형으로 확장 검토.

## 10. 씬 구성

- `Engine/Scene.h`를 상속받는 `MainScene`, `LobbyScene`, `GameScene` 3개 씬으로 구성한다.
- 진입 흐름: `MainScene`(타이틀, "시작하기" 버튼) → `LobbyScene`(스테이지 선택) → `GameScene`(플레이).
- `LobbyScene`에서 스테이지(1-1 / 1-2 / 1-3)를 선택하고, 선택한 스테이지로 `GameScene`에 진입한다.
- 스테이지는 **순차 잠금 해제** 방식이다 — 1-1을 클리어해야 1-2가, 1-2를 클리어해야 1-3이 열린다. 처음엔 1-1만 플레이 가능.

## 11. 경제 설계 (골드 보상 / 타워 가격)

밸런싱 단계에서 조정 가능한 시작점으로, 아래 수치를 초기값으로 둔다.

### 타워 구매 비용

| 타워 | 구매 비용 |
|---|---|
| 기본 타워 | 200 |
| 원거리 타워 | 350 |
| 범위 타워 | 500 |

### 타워 판매 환급

- 판매 시 환급액 = (구매 비용 + 지금까지 지불한 업그레이드 비용 총합) × 70%

### 타워 업그레이드 비용

- 최초 업그레이드(`_grade` 1→2) 비용은 구매 비용의 절반, 이후 등급마다 1.5배씩 증가 ([7절](#7-타워-스탯-설계) 등급 시스템 규칙과 동일).
- 기본 타워(구매가 200) 기준 예시: 1→2 = 100, 2→3 = 150, 3→4 = 225, 4→5 = 338(반올림)

### 풍선 처치 골드 보상 (등급 체인 기준)

| 등급 | Red | Blue | Green | Yellow | Pink | Black/White | Lead | Zebra | Rainbow | Ceramic |
|---|---|---|---|---|---|---|---|---|---|---|
| 보상 | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 | 12 | 15 |

- 보스1 처치 보상: 100 / 보스2 처치 보상: 400
- 하위 풍선으로 분열될 때 생성되는 하위 개체 자체는 별도 보상 없음 — 실제로 그 하위 개체를 처치했을 때만 해당 등급의 보상을 받는다.

### 웨이브 클리어 보너스

- `클리어 보너스(W) = 20 + 15 × W` (웨이브가 끝날 때 지급하는 추가 골드)

## 14. 권장 클래스 구조

기존 코드베이스의 `Game`(Singleton) + `Scene` + `Actor`/`MovableActor` 상속 구조를 그대로 따른다. 별도의 `GameManager`/`EnemyManager`/`TowerManager` 매니저 계층은 두지 않는다.

```text
Game (Singleton)
 ├─ Graphic
 ├─ TimeManager (Singleton)
 └─ SceneManager (Singleton)
     ├─ MainScene   : Scene
     ├─ LobbyScene  : Scene   (스테이지 1-1/1-2/1-3 선택)
     └─ GameScene   : Scene
         ├─ MapGenerator / PathFinder(A*)
         ├─ Tower       : Actor
         ├─ Bloon       : MovableActor   (Red~Ceramic 등급 체인)
         ├─ Boss        : MovableActor   (보스1/보스2, OBB 충돌)
         └─ Projectile  : Actor
```

## 15. 위험 요소와 대응

| 위험 요소 | 대응 방법 |
|---|---|
| 절차 생성으로 길이 없는 맵 생성 | 생성 직후 A*로 검증하고 실패 시 재생성 |
| 맵이 너무 단순하거나 어려움 | 최소 경로 길이와 미로 복잡도(분기 수)를 스테이지별로 제한 |
| 4주 내 기능 과다 | 스테이지 1-1/1-2/1-3, 타워 3종, 풍선 등급 체인(Red~Ceramic) + 보스 2종을 최소 목표로 고정, 그 이상은 확장 기능으로 분리 |
| WinAPI UI 구현 부담 | Direct2D 도형과 텍스트 렌더링 중심으로 단순하게 구현 |
| 밸런싱 시간 부족 | 적 체력·속도·보상과 타워 수치를 상수 테이블로 관리 |

## 16. 최소 완성 기준

- 스테이지 1-1 / 1-2 / 1-3 각각 유효한 미로형 맵과 적 이동 경로가 생성되며, 뒤로 갈수록 난이도가 상승한다.
- 매 게임마다 다른 유효 맵과 적 이동 경로가 생성된다.
- A* 알고리즘으로 시작점부터 도착점까지의 길을 계산한다.
- 적이 계산된 길을 따라 이동한다.
- 플레이어가 골드를 사용해 타워를 설치한다.
- 타워가 사거리 내 적을 공격해 제거한다.
- 적이 도착 지점에 도달하면 라이프가 감소한다.
- 풍선이 터지면 등급 체인(Red~Ceramic)에 따라 하위 풍선으로 이어진다.
- 웨이브, 게임 오버, 클리어 화면이 정상 동작한다.
