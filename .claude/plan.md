# WinAPI 기반 절차적 풍선 타워 디펜스 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | Balloon Defense (가칭) |
| 장르 | 2D 타워 디펜스 |
| 개발 기간 | 4주 |
| 개발 환경 | C++20, WinAPI, Direct2D + WIC |
| 핵심 기술 | 타일맵(Tile1/Tile2) 기반 렌더링, 타워 설치에 따른 A* 동적 경로 재탐색 |
| (구현 현황) | 타일맵 전체는 우선 Path로 채우고, 테두리 임의 시작/도착점 사이를 A*로 계산해 풍선이 따라감. 타워 설치에 따른 재탐색은 Tower 미구현으로 아직 미착수 |
| 목표 | 매번 달라지는 맵에서 풍선을 막는 싱글플레이 타워 디펜스 제작 |

플레이어는 골드를 사용해 타워를 설치하고, 생성 지점에서 목표 지점으로 이동하는 풍선 형태의 적을 처치한다. 맵 전체는 기본적으로 풍선이 이동 가능한 타일(`Tile1`)이며, 그 위에 타워 설치가 가능한 타일(`Tile2`)이 스테이지별로 미리 깔려 있다. 플레이어가 `Tile2` 칸에 타워를 설치하면 그 칸은 막히고, A* 알고리즘이 시작점~도착점 경로를 다시 계산해 풍선의 이동 경로가 그때그때 바뀐다.

| 항목 | 내용 |

| 타워 | 사거리 안의 적을 자동으로 탐지하여 공격 |

| 웨이브 | 일정 시간 또는 이전 웨이브 종료 후 적이 순차 등장 |

## 3. 타일맵과 시작/도착점

맵은 그리드 전체를 우선 `TileType::Path`(이동 가능)로 채운 뒤, 시작점·도착점을 테두리 셀 중에서 무작위로 뽑는다(`TileMap::GenerateRandomStartEndPoint`, [Client/TileMap.cpp:26](../Client/TileMap.cpp#L26)). 이후 [4절](#4-a-알고리즘-활용)의 A*가 이 두 점 사이 경로를 매 게임마다 다시 계산한다.

### 타일 종류

| 리소스 | 의미 | 구현 상태 |
|---|---|---|
| `Resource/Tile1.png` | 풍선이 이동 가능한 길 (`TileType::Path`) | ✅ 렌더링 완료 |
| `Resource/Tile2.png` | 타워를 설치할 수 있는 칸 (`TileType::Buildable`) | ⏳ 열거값만 존재, 배치 로직·렌더링 미구현 |

### 시작/도착점 규칙

- 축(좌우/상하)을 무작위로 고른 뒤, 시작점은 한쪽 벽에서, 도착점은 **반대쪽 벽**에서 각각 독립적으로 무작위 좌표를 뽑는다.
- 시작점이 모서리에 찍히더라도 도착점 생성 로직에는 영향이 없다 — 두 값은 서로 완전히 독립적인 난수다.
- 그리드 한 칸 크기(`BLOCK_SIZE`)는 타일 이미지 1장이 그려지는 크기와 같다.
- 현재는 `Buildable`(Tile2) 칸 배치가 구현되어 있지 않아 그리드 전체가 이동 가능 칸이다. 스테이지 데이터 기반 Tile2 지정은 이후 작업.

## 4. A* 알고리즘 활용

`PathFinder::FindPath`([Client/PathFinder.cpp:26](../Client/PathFinder.cpp#L26))가 [3절](#3-타일맵과-시작도착점)에서 정한 시작점~도착점 사이를 `GameScene::Init`에서 매 게임 시작 시 A*로 계산한다. 4방향 이동, 휴리스틱은 맨해튼 거리, Open 리스트는 `std::priority_queue` 기반 최소 힙이다.

풍선(`Bloon`)은 이 경로(`vector<Vector>`)를 `BloonFactory::Create`로 전달받아 웨이포인트를 순서대로 따라 이동한다.

### 디버그 표시

| 대상 | 색상 | 함수 |
|---|---|---|
| 시작점 | 초록 | `GameScene::renderStartEndDebug` |
| 도착점 | 빨강 | `GameScene::renderStartEndDebug` |
| A* 경로 웨이포인트 | 파랑 | `GameScene::renderPathDebug` |

## 5. 풍선 등급 체계와 충돌 판정

### 풍선 등급 체인 (`Client/BloonType.h` 기준)

Red → Blue → Green → Yellow → Pink → Black/White → Lead → Zebra → Rainbow → Ceramic 순으로 이어지는 색상 등급 체인을 그대로 사용한다.

**터짐 규칙(데미지 관통)**: 각 등급은 자신만의 "레이어 체력"을 갖는다. 한 발의 공격 데미지가 현재 등급의 레이어 체력을 넘으면, 초과분(leftover)이 그대로 하위 등급으로 이어져 즉시 재판정된다 — 공격 한 번이 여러 등급을 연쇄로 뚫고 지나갈 수 있다. 최하위 등급(Red)까지 도달하면 leftover 유무와 무관하게 하위 개체를 생성하지 않고 그대로 삭제(destroy)한다.

등급별 구성 (레이어 체력 / 터지면 생성되는 하위 개체):

| 등급 | 레이어 체력 | 하위 개체 |
|---|---|---|
| Red | 1 | 없음(최하위) |
| Blue | 1 | Red ×1 |
| Green | 1 | Blue ×1 |
| Yellow | 1 | Green ×1 |
| Pink | 1 | Yellow ×1 |
| Black | 1 | Pink ×2 |
| White | 1 | Pink ×2 |
| Lead | 1 | Black ×2 |
| Zebra | 1 | Black ×1 + White ×1 |
| Rainbow | 1 | Zebra ×2 |
| Ceramic | 10 | Rainbow ×2 |

처리 순서 (등급 X, 남은 데미지 D):

1. `D`만큼 X의 레이어 체력에서 깎는다.
2. 레이어 체력이 0 초과로 남으면 그대로 생존, 처리 종료(하위 등급으로 넘어가지 않음).
3. 레이어 체력이 0 이하가 되면 X는 터진다. 초과분(`leftover = -레이어체력`)이 있고 하위 등급이 있으면, 그 하위 등급에 `leftover`를 데미지로 그대로 넘겨 1번부터 반복한다.
4. 하위 등급이 없는 Red가 터지면 그대로 삭제한다.

예시:

| 공격력 | 대상 | 결과 |
|---|---|---|
| 1 | Red(레이어체력1) | 체력 1-1=0 → 터짐, 하위 등급 없음 → 삭제 |
| 1 | Blue(레이어체력1, 하위 Red 레이어체력1) | Blue 레이어(1) 정확히 소진, leftover=0 → Red 풍선(체력1) 생성, 생존 |
| 1(추가 피격) | 위에서 생성된 Red(레이어체력1) | 체력 0 → 터짐, 하위 없음 → 삭제 |
| 2 | Blue(레이어체력1, 하위 Red 레이어체력1) | Blue 레이어(1) 소진 후 leftover=1 → 즉시 Red 레이어(1)에 leftover 적용 → 0 → 하위 없음 → 삭제(Red 풍선 생성 없이 바로 사라짐) |

**이동 속도**: `Speed(tier) = 60 + 5 × (tier - 1)` (tier: Red=1 ~ Ceramic=10, 단위는 px/s에 준하는 임의 단위). Red=60, Blue=65, ..., Ceramic=105로 등급이 높을수록 조금씩 빨라진다. 보스1/보스2는 몸집이 크므로 고정값 30으로 더 느리게 이동한다.

### 충돌 판정

| 대상 | 판정 방식 | 이유 |
|---|---|---|
| 일반 풍선 (Red~Ceramic) | AABB | 회전 없이 이동만 하므로 축 정렬 사각형으로 충분 |
| 보스 풍선 | OBB | 직사각형 형태이며 타원형 경로를 따라 이동 방향에 맞춰 회전하기 때문에 회전을 반영한 충돌 박스가 필요 |

### 보스 풍선

- 형태: 직사각형(예: 사진 참고 — 위장 패턴의 캡슐/포탄형 몸체), 이동 방향에 따라 회전
- 자체 체력을 별도로 가지며, 그 체력이 0이 되면 파괴된다.
- 파괴 시 내부에 담고 있던 하위 개체를 방출한다 (컨테이너 역할).
- 보스는 2단계로 구성되며, 보스2가 보스1을 담고, 보스1이 Ceramic을 담는 체인 구조다.

| 보스 | 체력 | 파괴 시 방출 |
|---|---|---|
| 보스1 | 200 | Ceramic 4개 |
| 보스2 | 700 | 보스1 4개 |

## 6. UI 기획

UI는 풍선 타워 디펜스의 정보 구조를 참고하되, 아이콘·그래픽·명칭은 직접 제작한다.

- 창 해상도: **1440 × 1080** (4:3, [Client/TowerDefense.cpp:133](../Client/TowerDefense.cpp:133))
- 게임(그리드) 화면: 1200 × 900 (4:3, 좌측 상단 원점 기준)
- 우측 타워 패널: 240 × 900 (오른쪽 가장자리, y: 0 ~ 900)
- 하단 웨이브/컨트롤 패널: 1440 × 180 (아래쪽 가장자리, 창 전체 너비, y: 900 ~ 1080)
- 세 영역은 겹치지 않는다 (1200+240=1440, 900+180=1080)
- 그리드 칸수: **24 × 16**, `BLOCK_SIZE = 60`px (`Common/pch.h` 기준 — `GameAreaWidth=1440`÷60=24, `GameAreaHeight=960`÷60=16, 정사각형 셀)

> ⚠️ 위 "창 해상도 1440×1080 / 게임 화면 1200×900" 목업 수치는 레거시 값이며, 실제 코드 기준 창 크기는 `GWinSizeX × GWinSizeY`(`Common/pch.h`)입니다.

- 상단: 현재 웨이브, 남은 라이프, 골드
- 중앙: 절차 생성 맵, 길, 타워, 적, 투사체
- 오른쪽: 타워 구매 버튼과 선택된 타워의 정보
- 하단: 웨이브 시작, 일시정지, 게임 속도 조절
- 타워 선택 시: 공격 범위, 업그레이드, 판매 버튼 표시

## 7. 타워 스탯 설계

### 공통 프로퍼티

모든 타워는 다음 프로퍼티를 공통으로 가진다.

| 프로퍼티 | 타입 | 의미 |
|---|---|---|
| `_attackRange` | float | 공격 사거리 |
| `_damage` | float | 공격 데미지 |
| `_attackSpeed` | float | 공격 속도(초당 공격 횟수 또는 공격 주기) |
| `_grade` | int32 | 현재 등급, 1부터 시작 |
| `_canUpgrade` | bool | 다음 등급으로 업그레이드 가능 여부(최고 등급이면 false) |
| `_upgradeCost` | int32 | 다음 등급으로 올리는 데 필요한 비용 |
| `_attackCount` | int32 | 한 번의 공격으로 명중시킬 수 있는 풍선 개수 |

### 등급 시스템

- `_grade`는 1부터 시작하며, 업그레이드할 때마다 `_upgradeCost`를 지불하고 `_grade`가 1씩 오른다.
- 최대 등급은 5로 고정한다. `_grade == 5`가 되면 `_canUpgrade = false`로 더 이상 업그레이드할 수 없다.
- `_damage`: 선형 증가 (예: 등급마다 정해진 값만큼 증가 — 1 → 3처럼 등급별 목표값 테이블로 관리, 배율 아님)
- `_upgradeCost`: 배율 증가, 등급마다 1.5배
- `_attackSpeed`: 배율 증가, 등급마다 1.5배
- 정확한 데미지 테이블 값은 밸런싱 단계(3주차)에서 확정한다.
- **업그레이드 범위는 타워 인스턴스 단위다.** 맵에 배치된 타워 하나를 업그레이드해도 같은 종류의 다른 타워(맵에 이미 놓인 것/앞으로 놓을 것 모두)는 영향받지 않는다 — 전역 리서치형 업그레이드가 아니라 개별 타워 스탯 변경이다.

### 타워별 차별화

타워는 다음 3종으로 구성한다. 공격 사거리 판정 형태(방향성/원형)와 기본 사거리 길이로 구분한다.

| 타워 | 공격 판정 | 설명 |
|---|---|---|
| 기본 타워 | 방향성(전방) | 타워가 바라보는 방향(앞쪽)만 공격 — 원형이 아니라 정면 방향만 판정 |
| 범위 타워 | 원형 | 사거리 안에 들어오는 풍선을 방향 상관없이 전방위로 공격 |
| 원거리 타워 | 원형 | 범위 타워와 같은 원형 판정이지만, 기본 `_attackRange`가 더 긴 타워 |

- 타워 종류별 초기 스탯(`_attackRange`, `_damage`, `_attackSpeed`, `_attackCount`)은 전부 placeholder로 1을 사용한다. 공격 범위를 실제로 렌더링해서 눈으로 확인한 뒤 밸런싱 단계에서 수정한다.
- 기본 타워의 "바라보는 방향"은 배치 시 고정이 아니라, **타겟팅한 적을 향해 회전**한다.
- 지금 단계는 `Tower` 공통 프로퍼티 기획까지만 정리하고, 3종 타워 각각의 서브클래스(공격 판정 형태 포함)와 구체 수치 구현은 추후 진행한다.

## 8. 웨이브 설계

- 스테이지 전체에서 총 **30라운드**로 고정한다(스테이지마다 라운드 수를 달리하지 않는다).
- 한 라운드는 여러 개의 **서브웨이브**(같은 등급 풍선을 연속으로 스폰하는 그룹)로 구성되고, 서브웨이브 사이에는 대기 시간(지연)이 있다.
  - 예: 1라운드는 [빨간풍선 20개]처럼 서브웨이브가 1개일 수 있고, 후반 라운드는 [빨간풍선 X개 → N초 대기 → 파란풍선 Y개 → N초 대기 → 초록풍선 Z개]처럼 여러 개로 늘어난다.
- 라운드마다 필요한 값
  1. 풍선 종류(색상)
  2. 개수
  3. 스폰 간격(초, 서브웨이브 내부에서 풍선과 풍선 사이)
  4. 라운드 안의 서브웨이브 개수
  5. 서브웨이브 사이 대기 시간(초)
- 이 값들은 라운드 번호로부터 공식으로 계산한다(수동으로 하나하나 채워 넣지 않는다).

### 총 스폰 수량

`TotalCount(R) = base + growth × (R-1)`, `base=20`, `growth=10` — 1라운드=20마리, 2라운드=30마리, ..., 30라운드=310마리.

### 등급별 가중치와 등장/은퇴 라운드

풍선 등급마다 "언제부터 등장하는지(unlockRound)", "가중치(weight, 어려운 등급일수록 큼)", "언제 은퇴하는지(retireRound, 0이면 계속 등장)"를 정의한다. 그 라운드에 등장 중인 등급들의 가중치 비율대로 `TotalCount(R)`을 나눠, 등장 중인 등급 하나당 서브웨이브 하나를 만든다.

| 등급 | weight | 등장 라운드 | 은퇴 라운드 |
|---|---|---|---|
| Red | 1 | 1 | 19 |
| Blue | 2 | 3 | 19 |
| Green | 3 | 5 | 19 |
| Yellow | 4 | 7 | - |
| Pink | 5 | 9 | - |
| Black | 6 | 12 | - |
| White | 6 | 12 | - |
| Lead | 7 | 15 | - |
| Zebra | 8 | 18 | - |
| Rainbow | 9 | 22 | - |
| Ceramic | 10 | 26 | - |

- 예: 20라운드부터는 Red/Blue/Green이 은퇴해서 더 이상 나오지 않는다(체력이 너무 낮아 의미가 없어짐).
- 라운드가 늘어날수록 등장 가능한 등급 수가 늘고, 등장 중인 등급 중 가중치가 높은(상위) 등급의 비중이 커진다.
- weight/unlockRound/retireRound 수치는 밸런싱 단계에서 조정 가능한 시작점이다.

### 스폰 간격 / 서브웨이브 사이 대기 시간

- `SpawnInterval(R) = max(0.3, 1.0 - 0.05 × (R-1))` (초) — 라운드가 진행될수록 서브웨이브 내부 스폰 간격이 짧아지다가 0.3초에서 하한.
- 서브웨이브 사이 대기 시간은 고정값 **2초**를 사용한다(밸런싱 단계에서 조정 가능).

### 보스 등장

- 현재 `BloonColor`에 보스 등급이 정의되어 있지 않아 이번 범위에서는 보스 등장 로직을 구현하지 않는다. 보스 등급 추가 시 별도 설계.

## 9. 투사체 설계

- 속도(`_speed`)는 placeholder로 1을 사용, 실제 날아가는 속도를 보고 밸런싱 단계에서 조정한다.
- 이동 방식: 유도(호밍) 없이 발사 시점의 방향으로 회전 없이 직진한다.
- 모양: 기본은 원형. 다트류처럼 회전이 필요한 투사체는 추후 타원형으로 확장 검토.

## 10. 씬 구성

- `Engine/Scene.h`를 상속받는 `MainScene`, `LobbyScene`, `GameScene` 3개 씬으로 구성한다.
- 진입 흐름: `MainScene`(타이틀, "시작하기" 버튼) → `LobbyScene`(스테이지 선택) → `GameScene`(플레이).
- `LobbyScene`에서 스테이지를 선택하고, 선택한 스테이지로 `GameScene`에 진입한다. 우선 스테이지 1개(1-1)만 구현하므로 초기 버전은 선택 목록이 1-1 하나뿐이며, 1-2 / 1-3은 시간이 되면 추가한다.
- 스테이지는 **순차 잠금 해제** 방식이다 — 1-1을 클리어해야 1-2가, 1-2를 클리어해야 1-3이 열린다(스테이지가 여러 개로 늘어난 이후에 적용). 처음엔 1-1만 플레이 가능.

## 11. 경제 설계 (골드 보상 / 타워 가격)

밸런싱 단계에서 조정 가능한 시작점으로, 아래 수치를 초기값으로 둔다.

### 타워 구매 비용

| 타워 | 구매 비용 |
|---|---|
| 기본 타워 | 200 |
| 원거리 타워 | 350 |
| 범위 타워 | 500 |

### 타워 판매 환급

- 판매 시 환급액 = (구매 비용 + 지금까지 지불한 업그레이드 비용 총합) × 70%

### 타워 업그레이드 비용

- 최초 업그레이드(`_grade` 1→2) 비용은 구매 비용의 절반, 이후 등급마다 1.5배씩 증가 ([7절](#7-타워-스탯-설계) 등급 시스템 규칙과 동일).
- 기본 타워(구매가 200) 기준 예시: 1→2 = 100, 2→3 = 150, 3→4 = 225, 4→5 = 338(반올림)

### 풍선 처치 골드 보상 (등급 체인 기준)

| 등급 | Red | Blue | Green | Yellow | Pink | Black/White | Lead | Zebra | Rainbow | Ceramic |
|---|---|---|---|---|---|---|---|---|---|---|
| 보상 | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 | 12 | 15 |

- 보스1 처치 보상: 100 / 보스2 처치 보상: 400
- 하위 풍선으로 분열될 때 생성되는 하위 개체 자체는 별도 보상 없음 — 실제로 그 하위 개체를 처치했을 때만 해당 등급의 보상을 받는다.

### 웨이브 클리어 보너스

- `클리어 보너스(W) = 20 + 15 × W` (웨이브가 끝날 때 지급하는 추가 골드)

## 14. 권장 클래스 구조

기존 코드베이스의 `Game`(Singleton) + `Scene` + `Actor`/`MovableActor` 상속 구조를 그대로 따른다. 별도의 `GameManager`/`EnemyManager`/`TowerManager` 매니저 계층은 두지 않는다.

```text
Game (Singleton)
 ├─ Graphic
 ├─ TimeManager (Singleton)
 └─ SceneManager (Singleton)
     ├─ MainScene   : Scene
     ├─ LobbyScene  : Scene   (스테이지 선택, 우선 1-1 하나만)
     └─ GameScene   : Scene
         ├─ MapGenerator / PathFinder(A*)
         ├─ Tower       : Actor
         ├─ Bloon       : MovableActor   (Red~Ceramic 등급 체인)
         ├─ Boss        : MovableActor   (보스1/보스2, OBB 충돌)
         └─ Projectile  : Actor
```

## 15. 위험 요소와 대응

| 위험 요소 | 대응 방법 |
|---|---|
| 절차 생성으로 길이 없는 맵 생성 | 생성 직후 A*로 검증하고 실패 시 재생성 |
| 맵이 너무 단순하거나 어려움 | 최소 경로 길이와 미로 복잡도(분기 수)를 스테이지별로 제한 |
| 4주 내 기능 과다 | 스테이지 1개(1-1), 타워 3종, 풍선 등급 체인(Red~Ceramic) + 보스 2종을 최소 목표로 고정, 1-2/1-3을 포함한 그 이상은 확장 기능으로 분리 |
| WinAPI UI 구현 부담 | Direct2D 도형과 텍스트 렌더링 중심으로 단순하게 구현 |
| 밸런싱 시간 부족 | 적 체력·속도·보상과 타워 수치를 상수 테이블로 관리 |

## 16. 최소 완성 기준

- 스테이지 1개(1-1)에서 유효한 맵과 적 이동 경로가 정상 동작한다. 1-2 / 1-3은 시간이 되면 추가하며, 뒤로 갈수록 난이도가 상승한다.
- 매 게임마다 다른 유효 맵과 적 이동 경로가 생성된다.
- A* 알고리즘으로 시작점부터 도착점까지의 길을 계산한다.
- 적이 계산된 길을 따라 이동한다.
- 플레이어가 골드를 사용해 타워를 설치한다.
- 타워가 사거리 내 적을 공격해 제거한다.
- 적이 도착 지점에 도달하면 라이프가 감소한다.
- 풍선이 터지면 등급 체인(Red~Ceramic)에 따라 하위 풍선으로 이어진다.
- 웨이브, 게임 오버, 클리어 화면이 정상 동작한다.
