## 1주차 — 엔진 기반 + 맵/경로

> **산출물**: 1-1/1-2/1-3 각각 다른 미로 맵이 생성되고, A*로 계산한 경로를 풍선 한 마리가 시작점→도착점까지 따라간다. F1으로 그리드·경로 디버그 뷰를 켤 수 있다.

### 1-1. 그리드 / 타일 시스템
- `Grid` 클래스 신설 — 20 × 15 타일 (`plan.md` 3절)
- 셀 상태는 **길 / 설치 가능** 두 가지만 (`enum class CellState`)
- 화면 좌표 ↔ 셀 좌표 변환은 기존 [Common/pch.h](../Common/pch.h)의 `Cell::ConvertToCEll` 재사용
- 셀별 액터 보관은 기존 `GridInfo` 구조체 활용

### 1-2. 미로 맵 생성기 (`MapGenerator`)
- 시작점: 왼쪽 가장자리 무작위 / 도착점: 오른쪽 가장자리 무작위
- 미로 알고리즘으로 시작점~도착점 경로 생성
- 스테이지별 난이도 가중치 로드 (미로 복잡도: 분기 수, 막다른 길 비율, 경로 길이)
  - ⚠️ **가중치 구체 수치는 미정** — 우선 임의값(placeholder)으로 구현하고, 3주차 7-7 "실측 기반 수치 조정"에서 실제 플레이 화면을 보고 확정한다.
- 길이 아닌 **모든** 칸을 설치 가능으로 확정
- 생성 → 검증 → 실패 시 재생성 루프
  - 최대 재시도 **10회**, 초과 시 미리 만들어둔 고정 폴백 맵 사용

### 1-3. A* 경로 탐색 (`PathFinder`)
- G / H / F 비용, 휴리스틱은 맨해튼 거리 (`plan.md` 4절)
- 맵 생성 직후 유효성 검증에 사용 (경로 없음 / 너무 짧음 → 재생성, 1-2와 동일하게 최대 10회 + 폴백 맵)
- 계산된 경로 1개를 저장해 모든 풍선이 공유

### 1-4. 씬 골격
- 0주차에서 구현한 `Scene` / `SceneManager` 위에 `GameScene`만 우선 올림
- `MainScene` / `LobbyScene`은 **이번 주에는 만들지 않는다** — 클래스 생성을 포함한 전체 구현을 3주차 3-1로 이연

### 1-5. 디버그 렌더 (개발 도구)
- 그리드 라인, 셀 상태 색 구분, A* 경로 하이라이트
- 토글 키 배정 (예: F1)
- **이번 주 작업을 눈으로 검증하는 도구이므로 마지막이 아니라 1-2와 병행해서 만듭니다**

### 1-6. 풍선 이동 (최소 확인용)
- `Bloon`이 `MovableActor`를 상속해 저장된 경로를 따라 이동
- 속도 공식 `60 + 5 × (tier-1)` 적용 (`plan.md` 5절)
- 도착 지점 도달 시 제거 (라이프 감소는 2주차)

### 📚 공부해야 할 것

| 주제 | 왜 필요한가 | 확인 포인트 |
|---|---|---|
| **미로 생성 알고리즘** | 1-2의 핵심 | DFS 백트래킹(가장 구현 쉬움, 긴 통로 생성), Prim, Recursive Division 비교 → **DFS 백트래킹으로 시작 권장**. "벽을 허무는" 방식과 "길을 놓는" 방식의 차이 |
| **A\* 경로 탐색** | 1-3의 핵심, 프로젝트 최대 학습 목표 | G/H/F 비용의 의미, 휴리스틱이 **실제 비용을 넘지 않아야**(admissible) 최단 경로가 보장된다는 점, Open/Closed 리스트 관리, 4방향 이동이면 맨해튼·8방향이면 유클리드/대각 휴리스틱 |
| **`std::priority_queue`** | A*의 Open 리스트 구현 | 기본이 **최대 힙**이라 F 비용 최소를 뽑으려면 비교자를 뒤집어야 함(`std::greater` 또는 커스텀 `operator()`), `top`/`pop`이 분리되어 있음 |
| **난수 생성 (C++11 이상)** | 맵을 매번 다르게 생성 | `rand()` 대신 `std::mt19937` + `std::uniform_int_distribution`. **시드를 고정하면 같은 맵이 재현**되어 디버깅에 유용 |
| **좌표계 변환** | 화면 픽셀 ↔ 그리드 셀 | [Common/pch.h](../Common/pch.h)의 `Cell::ConvertToCEll`이 이미 하는 일, 정수 나눗셈의 음수 처리 함정 |
| **Direct2D 기본 도형 그리기** | 1-5 디버그 뷰 | `DrawLine`/`DrawRectangle`/`FillRectangle`/`DrawEllipse`, `ID2D1SolidColorBrush` 생성 비용이 크므로 **매 프레임 만들지 말고 캐싱** |
| **고정 프레임 루프와 delta time** | 프레임률과 무관하게 같은 속도로 이동 | 이동은 `speed * deltaTime`, [Engine/TimeManager.h](../Engine/TimeManager.h)가 이미 계산 중 |

## 2주차 — 전투 코어

> **산출물**: 타워 3종이 풍선을 타겟팅해 투사체를 쏘고, 풍선이 등급 체인을 따라 Red까지 분열하며, 10웨이브가 순서대로 진행되고 보스가 등장한다.

### 2-1. 풍선 등급 체인 완성
- `BloonColor` Red~Ceramic, HP는 Ceramic만 10 나머지 1 (`plan.md` 5절)
- **터짐 규칙**: 죽으면 바로 아래 등급 1개 생성, Red는 하위 없이 destroy
- 등급별 이동 속도 적용

### 2-2. 보스 풍선
| 보스 | 체력 | 파괴 시 방출 | 속도 |
|---|---|---|---|
| 보스1 | 200 | Ceramic 4개 | 30 |
| 보스2 | 700 | 보스1 4개 | 30 |

- 직사각형 형태, **이동 방향에 따라 회전**
- 보스2 → 보스1 → Ceramic 으로 이어지는 2단 컨테이너 체인

### 2-3. 충돌 시스템
- 일반 풍선: **AABB** (회전 없음)
- 보스 풍선: **OBB** (회전하므로 SAT 판정 필요)
- 투사체 ↔ 풍선 충돌 처리, `Actor`의 `OnEnter`/`OnStay`/`OnExit` 훅 활용
- 디버그 렌더에 충돌 박스 표시 추가 (1-5 확장)

### 2-4. 타워 3종
| 타워 | 공격 판정 |
|---|---|
| 기본 타워 | 방향성(전방)만 판정 |
| 범위 타워 | 원형 전방위 |
| 원거리 타워 | 원형, `_attackRange`가 더 김 |

- 공통 프로퍼티는 [Client/Tower.h](../Client/Tower.h)에 이미 정의됨
- 초기 스탯은 전부 placeholder `1` — **공격 범위를 화면에 그려서 눈으로 보고** 조정
- 타겟팅한 적을 향해 회전 (배치 시 고정 아님)
- `_attackCount`만큼 한 번에 명중

### 2-5. 투사체
- 발사 시점 방향으로 **회전 없이 직진** (호밍 아님)
- 모양: 원형 / 속도 placeholder `1`

### 2-6. 웨이브 시스템
- 스테이지당 **10웨이브**, Wave W에서 등급 W가 신규 등장 (Wave1=Red … Wave10=Ceramic)
- 수량: `TotalCount(W) = 20 × mul + 15 × mul × (W-1)`, mul은 1-1=1.0 / 1-2=1.3 / 1-3=1.6
- 스폰 간격: `max(0.3, 1.0 - 0.05 × (W-1))`초
- 보스 등장 웨이브: 1-1 = 5, 10 / 1-2 = 4, 7, 10 / 1-3 = 3, 6, 8, 10
- 웨이브가 진행될수록 상위 등급 비중 증가

### 2-7. 라이프 / 골드 기초
- 초기 라이프 100, 초기 골드 600
- 풍선 도착 시 라이프 감소, 처치 시 골드 획득 (보상표는 `plan.md` 11절)
- 라이프 0 → 게임 오버 상태 진입 (화면은 3주차)

### 📚 공부해야 할 것

| 주제 | 왜 필요한가 | 확인 포인트 |
|---|---|---|
| **AABB 충돌 판정** | 일반 풍선 충돌 | 두 사각형이 **겹치지 않는 조건**을 먼저 쓰고 부정하는 게 실수가 적음 (`a.right < b.left \|\| a.left > b.right \|\| ...`) |
| **SAT (분리축 정리)** | 보스 OBB 충돌 — 2주차 최대 난관 | "어떤 축에 투영했을 때 두 도형이 떨어져 있으면 충돌 아님". OBB 2개면 **검사할 축은 4개**(각 사각형의 변 법선 2개씩), 2D에서는 축이 곧 변의 법선 |
| **벡터 수학** | 타겟팅, 회전, 투영 전부 | 내적(각도·투영), 외적(2D에서 좌우 판별), 정규화. [Common/pch.h](../Common/pch.h)의 `Vector`에 `Dot`/`Cross`/`Normalize`/`Rotate`가 **이미 구현되어 있으니 새로 만들지 말 것** |
| **`atan2f`로 각도 구하기** | 보스·기본 타워가 이동/타겟 방향으로 회전 | `atan2f(y, x)` 인자 순서 주의(y가 먼저), 반환은 **라디안** — [Common/Util.h](../Common/Util.h)의 `RadianToDegree` 활용 |
| **부채꼴(방향성) 범위 판정** | 기본 타워의 전방 공격 | 거리 검사 + 내적으로 각도 검사 2단계. `dot(정규화된 전방벡터, 정규화된 타겟방향) >= cos(시야각/2)` |
| **객체 풀링 (Object Pool)** | Ceramic 1개 → Red까지 분열하면 액터가 폭증 | `new`/`delete` 반복의 비용, [Engine/Actor.h:34](../Engine/Actor.h#L34)에 `IObjectPool` 주석이 이미 있음. 풀에서 꺼낼 때 **상태 초기화 누락**이 대표적 버그 |
| **팩토리 패턴** | 등급별 풍선 생성 (`BloonColor` → 인스턴스) | 생성 로직을 한 곳에 모아 터짐 체인이 재귀적으로 하위 등급을 만들 수 있게 |
| **상속 vs 컴포지션** | 타워 3종 설계 판단 | "공격 판정 형태"만 다르다면 서브클래스 3개보다 **판정 전략을 멤버로 갖는 방식**이 나을 수 있음 — 직접 비교해보고 선택 |
| **컨테이너 순회 중 원소 추가/삭제** | 풍선이 터지며 새 풍선이 생기는 순간 | `vector` 순회 도중 `push_back`하면 **이터레이터 무효화**. 프레임 끝에 몰아서 처리하는 지연 처리(`_pendingKill`, PostUpdate) 패턴 |
| **광역 판정 최적화 (Broad Phase)** | 풍선 100마리 × 타워 여러 개 = 전수 검사 폭발 | 이미 있는 그리드를 재사용해 **주변 셀만 검사**하는 공간 분할. [Common/pch.h](../Common/pch.h)의 `GridInfo`가 이 용도 |

## 3주차 — 씬 · UI · 경제

> **산출물**: 타이틀 → 스테이지 선택 → 플레이 → 클리어/게임오버까지 끊김 없이 도는 알파 버전. **이 주차 끝에 기능 개발이 완료되어야 합니다.**

### 3-1. 씬 3종 완성
- 진입 흐름: `MainScene`(타이틀) → `LobbyScene`(스테이지 선택) → `GameScene`(플레이)
- **스테이지 순차 잠금 해제**: 1-1 클리어해야 1-2, 1-2 클리어해야 1-3 (처음엔 1-1만)
- 씬 전환 시 리소스 정리 / 재초기화

### 3-2. HUD
- 상단: `웨이브 3 / 10`, `라이프 ♥100`, `골드 $600`
- 하단: 웨이브 시작, 일시정지, 배속 x1 / x2
- 레이아웃은 `plan.md` 6절 목업 기준

### 3-3. 타워 상호작용 UI
- 우측 구매 패널: 기본 $200 / 원거리 $350 / 범위 $500
- 설치 가능 칸 하이라이트, 길 위에는 설치 불가
- 타워 선택 시: **공격 범위 원 표시**, 업그레이드 / 판매 버튼

### 3-4. 업그레이드 · 판매
- **업그레이드는 타워 인스턴스 단위** — 같은 종류의 다른 타워는 영향받지 않음 (전역 리서치 아님)
- 최대 등급 5, `_grade == 5`면 `_canUpgrade = false`
- `_upgradeCost` 등급마다 1.5배 / `_attackSpeed` 등급마다 1.5배 / `_damage`는 선형 증가
- 판매 환급 = (구매가 + 누적 업그레이드 비용) × 70%

### 3-5. 경제 밸런싱
- 풍선 처치 보상 Red 1 ~ Ceramic 15, 보스1 100 / 보스2 400
- 분열로 생성된 하위 개체는 **처치했을 때만** 보상
- 웨이브 클리어 보너스 `20 + 15 × W`

### 3-6. 게임 상태 화면
- 게임 오버 / 스테이지 클리어 화면
- 클리어 시 다음 스테이지 잠금 해제 반영

### 3-7. 실측 기반 수치 조정
- placeholder `1`로 둔 값들(`_attackRange`, `_damage`, `_attackSpeed`, 투사체 속도)을 **실제 플레이 화면을 보고** 확정
- 등급별 데미지 테이블 확정
- 미로 복잡도 가중치가 1-1 < 1-2 < 1-3으로 실제 체감되는지 검증

### 📚 공부해야 할 것

> ⚠️ **DirectWrite가 아직 프로젝트에 없습니다.** 현재 링크된 라이브러리는 `d2d1.lib`, `windowscodecs.lib`, `ole32.lib`뿐입니다([Client/Game.cpp:6-8](../Client/Game.cpp#L6-L8)). HUD의 웨이브·라이프·골드 텍스트를 그리려면 `dwrite.lib` 추가와 `IDWriteFactory` 초기화가 **선행되어야 합니다.** 3주차 첫 작업으로 잡으세요.

| 주제 | 왜 필요한가 | 확인 포인트 |
|---|---|---|
| **DirectWrite 텍스트 렌더링** | HUD 전체가 여기 의존 | `IDWriteFactory` → `IDWriteTextFormat`(폰트·크기·정렬) → `ID2D1RenderTarget::DrawText`. `TextFormat`은 **매 프레임 만들지 말고 캐싱**, [Common/Util.h](../Common/Util.h)의 `FontSize` enum 활용 |
| **유한 상태 기계 (FSM)** | 씬 전환 + 게임 상태(진행/일시정지/클리어/오버) | 상태 진입·이탈 시점에 할 일(`Enter`/`Exit`)을 분리하면 리소스 정리 버그가 줄어듦 |
| **씬 전환 시 리소스 수명** | 씬을 바꿀 때 이전 씬의 액터·비트맵 정리 | 전환을 **프레임 도중에 하면 순회 중이던 컨테이너가 파괴됨** → 프레임 끝에 지연 전환 |
| **마우스 히트 테스트** | 타워 구매 버튼, 설치 위치 선택 | `WM_LBUTTONDOWN`의 `lParam`에서 좌표 추출, UI 영역과 맵 영역 판정 순서(**UI를 먼저** 검사해야 버튼 뒤에 타워가 설치되지 않음) |
| **타임 스케일 (배속 x1/x2)** | 하단 배속 버튼 | `deltaTime * timeScale`을 **모든** 업데이트에 일관되게 적용. 일시정지는 `timeScale = 0`으로 통일하면 코드가 단순해짐 |
| **데이터 주도 설계** | 타워 가격/보상표/웨이브 구성이 전부 상수 | 수치를 코드에 흩뿌리지 말고 테이블 하나로 모으기 — `plan.md` 15절 "밸런싱 시간 부족" 대응책 |
| **UI 레이아웃 계산** | 1920×1080 고정 해상도 기준 배치 | 절대 좌표로 박되 **상수로 빼두기**. `plan.md` 6절 목업을 좌표로 옮기는 작업 |
| **진행도 저장 (선택)** | 스테이지 순차 잠금 해제 상태 유지 | 게임 재시작 시에도 유지하려면 파일 저장 필요. **범위 밖이면 메모리 유지만으로 충분** — 무리해서 넣지 말 것 |
