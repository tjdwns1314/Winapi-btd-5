# 커밋 컨벤션

이 저장소(Winapi-btd-5)는 **Gitflow** 브랜치 전략을 따릅니다. 커밋을 생성할 때는 이 문서의 규칙을 따르세요.

## 브랜치 전략 (Gitflow)

- `main` — 배포 가능한 안정 상태만 유지합니다. 직접 커밋하지 않습니다.
- `develop` — 다음 릴리스를 위한 통합 브랜치입니다.
- `feature/*` — 신규 기능 개발. `develop`에서 분기, `develop`으로 병합.
- `release/*` — 릴리스 준비(버그 수정, 문서 정리). `develop`에서 분기, `main`과 `develop`으로 병합.
- `hotfix/*` — 운영 중 긴급 수정. `main`에서 분기, `main`과 `develop`으로 병합.

## 커밋 메시지 형식

```
<type>: <subject>

<body (선택, 필요할 때만)>
```

- `subject`(설명)는 **최대한 간결하게** 한 줄로 작성합니다. 불필요한 부연 설명을 붙이지 않습니다.
- `body`는 꼭 필요한 경우에만 작성하며, 역시 간결하게 유지합니다.
- **Co-authored-by 트레일러는 절대 추가하지 않습니다.**

### type 목록

| type | 의미 |
|---|---|
| `feat` | 신규 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 코드 구조 개선 |ㄴ
| `style` | 포맷팅 등 코드 의미에 영향 없는 변경 |
| `docs` | 문서 변경 |
| `test` | 테스트 추가/수정 |
| `chore` | 빌드, 설정 등 기타 잡무 | 
| `perf` | 성능 개선 |
| `revert` | 이전 커밋 되돌리기 |

### 예시

```
feat: 타워 사거리 표시 원 추가
fix: 풍선 터짐 체인 색상 오류 수정
refactor: Actor Update/Render 순서 정리
docs: 커밋 컨벤션 문서 추가
```

## 주의사항

- Co-authored-by 등 작성자 관련 트레일러를 커밋 메시지에 넣지 않습니다.
- description(제목)은 장황하게 쓰지 않고 핵심만 남깁니다.
- 사용자가 "커밋해줘"라고 요청할 때마다 이 문서를 먼저 읽고 규칙을 적용합니다.
